# Cursive

An interactive reading prototype with locally saved questions and Gemini-generated reading receipts.

## Responsive app layout

Phone screens use a single column with safe-area spacing, proportional artwork, and touch-sized controls. Tablets keep bounded reading columns. From 1100px, selection and article introductions use two columns, reading pages use a sticky illustration beside the text, and the transcript uses a separate selection workspace. Desktop text sizes do not shrink with the window height.

The shared layout rules are in `client/src/responsive.css`. Layout checks cover all nine screens at 320, 390, 768, 1024, 1280, and 1440px, including narrow portrait and short landscape viewports.

## Run locally

1. Run `npm run install:all` if dependencies are missing.
2. Copy `server/.env.example` to `server/.env` and set `GEMINI_API_KEY`.
3. Run `npm run dev` from the project root.
4. Open the client address printed by Vite. The client proxies `/api` to port 5001.

`GEMINI_MODEL` defaults to `gemini-3.5-flash`. The API key stays in the ignored server environment file and is never sent to the client. MongoDB is optional; leave `MONGO_URI` empty to use the reading and receipt flow without a database.

## Reading receipts

- **Save Question** stores each question and interaction state in this browser's local storage.
- **Submit Answers** saves the current questions locally without navigation or a Gemini call.
- **Next Article** opens `/receipt`. That page sends the saved questions, their insertion points, and the article to the server for Gemini analysis.
- A receipt is cached locally against the exact question text and interaction states. Refreshing an unchanged receipt uses its cache. Changed questions produce a new receipt.
- `/receipt/example` displays a clearly marked example generated by Gemini from the reference design's questions. It does not change the reader's saved questions.
- Reader transcripts are preserved verbatim. Analysis distinguishes match, answered, open, outside, view, unclear, and skipped. Interaction colors are independent of these outcomes.
- Generation errors show a retry option and retain the saved questions. No fabricated fallback analysis is shown.
- **Share receipt** opens native sharing where available, or downloads a text copy. The receipt's Next Article link returns to the plate, where the India flag opens Article 02.

## Article 02: The Call

- **The Call** button opens the nine-line transcript at `/read/2/call`.
- Choose up to five lines. The main continue button enables at five; **Proceed with 0–4** allows a smaller selection.
- Continuing returns to Article 02 with game mode enabled. Clicking a paragraph's three-dot blank opens the selected lines as answer options.
- Transcript selections and filled blanks are stored locally. Removing a selected line also clears any blank filled with that line, keeping answers consistent with the available options.
- The reader can review the transcript, replace choices, and clear or change each answer. Used options are green and move to the bottom of each dot menu.
- Article 02's **Submit Answers** only saves locally. **Next Article** opens `/receipt/2`, where Gemini writes a receipt from the final selections, placements and selected-but-unused lines.
- The Lift receipt uses the supplied September 21 test report's three reference placements (A ← L4, B ← L3, C ← L6), distinguishes atmosphere from demonstration, and recognizes a complete rotation. It does not display a grade.
- No paragraph-reading or selection-history events have been recorded. The receipt therefore describes final choices and does not claim that a reader changed their mind after reading a paragraph. Unverified voice-cloning claims from the test report are excluded.
- Lift receipts have a separate local cache that is invalidated when a selection or placement changes.

## Checks

```sh
npm test --prefix server
npm run build --prefix client
npm run lint --prefix client
```

The report supplied with the design is a test report rather than a formal specification. Its identified failures informed the analysis prompt: no scores, opinions are not reporting holes, outside facts are classified separately, and source questions are not automatically treated as outcome questions.
